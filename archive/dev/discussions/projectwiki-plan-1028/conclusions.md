# ProjectWiki 首版讨论结论

日期：2026-10-28。状态：讨论与首版实现完成。

## 已采用的设计

- 根目录 `docs/`、`dev/`、`archive/` 并列。稳定知识持续原位维护，已结束过程与整篇失去当前职责的文档才归档。
- 整页归档使用 `archive/<原相对路径>`，默认不改名；新建时检查历史，归档目标存在时停止，不能覆盖。
- 按任务逐层读取，关键规则直接写在 AGENTS.md；模块知识靠近源码，全局入口直接链接模块入口。
- 稳定知识面向人写作，解释对象、条件、行为与取舍，避免 AI 套话、翻译腔和内部行话。开发规范属于稳定知识。
- plan 维护步骤、进度和验收；roadmap 维护方向与入口；ADR 解释持续影响结构或契约的重要取舍。模块决定放在模块 docs/decisions，普通修复不强制建立三类文件。
- 日常检索减少历史干扰，按任务需要即可扩大搜索；搜索忽略规则不缩小文档检查范围。
- 已被完整替代或适用对象退役的 ADR 可以按生命周期规则归档，仍有效的 ADR 留在知识目录。无需为每次实施完成归档决定。

## 实际交付与验证

ProjectWiki 自身的介绍、需求、原则、设计、规范和接入指南已写入；`demo/` 提供可运行参考项目，`templates/` 提供最小接入组。工具提供本地检查、真实暂存检查、新建历史提示、确定性目录和整页归档预览。

最终实现修复了评审发现的角色降级、越根本地链接、目录误认历史文件以及缺失目标仍给迁移候选等问题。验证记录、输入原文与限制保存在首版接入系统计划的归档中。

## 保留的边界

首版不提供自动归档写入、旧历史布局的自动映射、正文状态解析、任意 Markdown 方言支持、存量告警基线或任意宿主门禁推断。JSON 生成目录包含历史，消费者按角色筛选；只有 `check --staged` 验证暂存内容，其余命令明确读取工作区。

下一步是选择真实项目接入并校准预算与规则，不能用本次小样本通过推断大仓库的耗时或迁移成本。原 Singular 和 UniverseAgent 保持只读调查范围。
