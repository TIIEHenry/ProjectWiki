# 开发规范

范围：NoteBox。状态：当前有效。

修改前明确目标、适用约束、实现位置和验证方式。普通局部修复可以在原任务或提交记录中写依据与结果；新增行为更新相应需求与测试。边界明确、没有重要风险或契约变化，也不需要多步骤协作或交接时，不另建设计和计划；标题计数、校验顺序等契约变化仍需更新相关设计。不要按提交次数或修改行数判断风险。

本项目使用 Python 3.10+ 和标准库。标题模块对外行为由 [模块需求](../../notes/docs/requirements.md) 规定，测试不能自行改变契约。

验证命令只登记在 [`docs/wiki.json`](../wiki.json) 的 `verify` 里，目前是 `notes/tests` 的单元测试。在项目根目录运行：

```sh
python3 scripts/wiki/wiki.py verify --root .
```

计划的验证记录直接用它的输出：输出写明 Git HEAD、未提交文件数、被测文件的哈希和每条命令的结果。人工核对的内容和已知限制写在后面。新增证据文件本身不使被验证源码变更。

[路线图](../../dev/roadmap.md) 记录方向与先后关系；实施计划记录一个工作的步骤与验收，具体工作从 [开发入口](../../dev/INDEX.md) 查找。只解释本次修复的理由写进提交信息；持续约束后续修改的写进设计或相关代码注释；有长期重要影响且需要解释替代方案的取舍写 ADR。任务进度只在对应任务或计划维护，路线图引用它，不抄执行流水。

正文使用直接、具体的中文。区分事实、推测与待办；不把预期写成已经验证的结果。
