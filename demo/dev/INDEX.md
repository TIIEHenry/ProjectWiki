# 开发入口

| 什么时候读 | 记录 |
|---|---|
| 了解后续方向与顺序 | [路线图](roadmap.md) |
| 评估标题是否应限制为单行 | [实施计划](plans/multiline-title.md) |
| 提交尚未核实的问题 | [待办收件箱](inbox/README.md) |
| 查看一次审查怎样记录问题、核对和方案 | [标题输入审查](reviews/2026-10-28-title-input/README.md) |

已结束的首次校验计划在 [归档](../archive/dev/plans/initial-title-validation.md)，全部历史记录见 [历史索引](../archive/INDEX.md)。它不能覆盖当前需求；是否需要读历史取决于任务。

本例的计划和模块入口足以接续工作，没有需要另设状态页的协调事项。接续时直接读计划，核对当前状态、源码变化与验证对象；不会因提交或模块增加而自动建立状态页。需要另设协调视图时，按 `scripts/wiki/workflow.md` 的“任务记录与状态页”判断。本例未接入执行套件，下面仅演示现有记录的角色绑定，不证明套件派工或恢复已经运行。

## 项目绑定示例

| 角色 | 本例的实际来源与职责 |
|---|---|
| 任务来源 | [多行标题计划](plans/multiline-title.md)，以路径识别任务；验收条件在计划引用的需求中 |
| 执行与协调记录 | 无执行套件、并发槽位或独立恢复记录；接续者在原计划维护步骤和验证记录 |
| 待处理项来源 | [收件箱](inbox/README.md)，分诊后在原条目链接计划或说明其他去向 |
| 验证入口 | 在本例根目录运行 `python3 scripts/wiki/wiki.py verify --root .`，结果保存在原计划 |
| 归档约定 | 计划完成或取消且剩余事项已有去向后，按 `scripts/wiki/workflow.md` 归档到 `archive/dev/plans/`；历史入口见本页上方 |

执行套件若要复用本例，应从本表找到原计划和收件箱，再声明它实际维护的执行记录；不复制计划步骤和需求正文。套件读取与结束条件按 `scripts/wiki/workflow.md` 的“与执行套件共用开发入口”核对。
