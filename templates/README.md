# 可复制模板

先复制 `project/` 内的文件到目标仓库，替换所有 `【待填：…】`，删除不适用内容，再填写 `docs/wiki.json`。模板配置不含 `remind`，因为代码与文档的对应关系只能按目标项目填写；按[接入指南](../docs/guides/adoption.md#8-设置文档同步提醒)补上，并安装 Git 钩子。在真实模块旁按需复制 `module/`，把模块路径登记到配置中。归档根 `archive/` 可在首次归档时建立。

小项目可在 `docs/overview.md` 的三个小节中分别维护需求、原则和设计。内容增长后再拆页；不要为通过检查创建空文档。

| 模板 | 使用时机 |
|---|---|
| [项目最小组](project/README.md) | 首次接入 |
| [模块最小组](module/README.md) | 模块需要独立知识入口 |
| [实施计划](plan.md) | 工作需要步骤、验收或跨会话交接 |
| [决策记录](decision.md) | 重要取舍需要长期解释 |
| [待办条目](inbox-item.md) | 记录尚待分诊的问题或建议 |

`plan.md`、`decision.md`、`inbox-item.md` 按需复制；普通局部修复可在现有任务或提交记录中保存目标、依据和验证结果。

正文先写对象、规则与依据，区分当前事实、目标和猜测。写验证结果时填写真实命令与验证对象；模板里的空位不能作为证据。文件名、类型目录和预算可以调整，原文应让未参加项目讨论的人也能理解。

可运行的完整示例见 [NoteBox](../demo/README.md)。工具和接入步骤见 ProjectWiki 的 [接入指南](../docs/guides/adoption.md)。
