## Functional requirements

Each requirement is a level-three heading that begins with its ID, for example `### APP-01`, and the first line below the heading gives the status. The acceptance criteria are listed one by one, each with a sub-ID, in a form that can be checked; the pattern "When ..., ..." can serve as a model. For items that can be tested, the tests cite the ID in their descriptive text; only what no command can prove is marked `(manual)` at the end and gets an acceptance check record. When a design and a plan are needed, the design document and the plan each cite the ID on a `Requirements:` line; do not create documents in order to complete the references. The format, the status values, and how new IDs are assigned are in the "Requirement entries" and "How IDs are assigned" sections of `scripts/wiki/en/formats.md`.
