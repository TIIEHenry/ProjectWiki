# 项目开发约束

- `docs/` 保存当前需求、原则和设计；`dev/` 保存候选方案、任务与进度；`archive/` 保存历史。按任务需要检索历史，不把历史正文直接当作当前规范。
- 【待填：忽略后会导致错误的全局硬约束，直接写出规则，不只放链接。】
- 控件尺寸、调用顺序等实现约束放在模块文档，不堆进本文件。
- 稳定知识面向人类阅读，写清具体对象、适用条件和行为，避免 AI 套话、翻译腔与未解释的内部简称。
- 新建文档路径不得含空格、`#`、`%` 或括号；复制模板后改成具体主题名。其余命名建议和 `check-new` 用法见 `scripts/wiki/README.md`。
- 整页归档到 `archive/<原相对路径>`，保持文件名与目录；目标已存在时停止，不覆盖。用 `python3 scripts/wiki/wiki.py archive <路径> --root .` 预览，再加 `--apply --expect <plan_sha256>` 执行，不手工移动文件和改链接。新建前检查对应历史，命中后判断恢复、延续或新主题，不把同名历史当作永久禁名。
- 涉及某模块时，先读该模块入口和适用契约，再核对实现与验证方式。
- 【待填：会持续变长的登记表，例如 `dev/progress/deferred-gaps.md`】按编号或关键词搜索，只读命中的行，不整篇读入。
- 状态行、核对行、需求条目、审查问题和待处理项的写法，以及需求编号和审查路号怎样分配，以 `scripts/wiki/formats.md` 为准；配置和规则名按名称在 `scripts/wiki/reference.md` 里搜索，不整篇读。
- 核对人、作者、负责人、签收人写成 `human:<名字>` 或 `agent:<名字>`。Agent 只能把自己写成 `agent:`，不得写成 `human:`；配置了 `remind` 并安装钩子后，提交里新增 `human:` 名字会出现 `[user]` 提醒。知识页核对后在标题下写 `核对：agent:<名字>，YYYY-MM-DD。`，会过期的页面同时写 `复核期限：YYYY-MM-DD。`。
- 一次审查放在 `dev/reviews/<开始日期>-<主题>/`，每一路一个文件，每条问题一个小节；核对、方案和签收写进问题小节，复查在核对表里追加一行，不新建文件。核对人不能是作者。路号由负责汇总的人分配。能写成已有文件里的一节，就不新建文件。
- AI 工具或技能生成的计划、报告、调研和草稿放进 `dev/`，不能写进 `docs/`；工具默认写到 `docs/` 时先改配置或生成后移走。
- 发现问题或想法但拿不准放哪里、要不要做时，按一条一文件写进 `dev/inbox/<类型>/<主题>.md`，至少记录状态、来源、观察或需求、核实依据和处置去向；不要直接改 `docs/`，也不要临时新建目录。处理完时写明去向，状态改为"已完成"，再用 `archive` 归档。
- 只暂存本次工作相关的文件，不还原或清理其他人和其他 Agent 的未提交改动。合并时两边都改过的文件做三方合并，不默认整份采用一边。
- 留下占位实现或 `TODO` 时写明原因、影响和清理时机；已知失败写明退出条件，不能以"改动前就是红的"为由一直不处理。
- 按改动范围运行 `python3 scripts/wiki/wiki.py verify --root .`。命令和运行目录只登记在 `docs/wiki.json` 的 `verify` 里，任一命令退出码不为 0 就是失败；模板只登记了文档检查，接入时补上项目自己的测试和构建命令。计划的验证记录用 `verify` 输出生成，不手写命令结果。
- 能由工具精确完成的步骤交给工具；核对行、复核期限续期、人工签收和需求状态由人或 Agent 判断后写，不让工具代写。
- 当前知识有变化时原位更新对应正文；普通修订由 Git 保留历史。不因每次提交机械新建计划或改写状态页。
- 新功能和行为变化在同一次改动中写或修改需求条目：编号标题、状态行、带子编号的可检查验收条件。设计文档写"对应需求："，计划写"覆盖需求："，测试在说明文字里写验收编号。能写测试的验收条目写测试；只有命令证明不了的才标"（人工验证）"并写验收核对记录。普通修复不新建需求，引用已有编号即可。
- 采用、替代或废止决策记录，或者设计、接口行为发生变化时，在同一次改动中更新仍描述旧结论的需求、设计、模块入口和本文件条目。按链接和关键词两种方式查找受影响的文档。推翻已采用决定的设计变更要补新的决策记录。
- 开始任务时运行 `python3 scripts/wiki/wiki.py remind --root .`。提交时 Git 钩子也会输出提醒。看到 `[agent]` 提醒，就更新对应文档，或者在提交信息最后一段写 `Docs-Reviewed: <名称> <理由>`；看到 `[user]` 提醒，除非用户已经要求这项修改，否则先向用户确认，并在总结里报告。不得用 `--no-verify` 跳过钩子。
- 日常 Wiki 搜索通过 `.ignore` 排除根 `archive/`。需要历史时定向搜索；`grep -R` 不读取 `.ignore`，常规查询可加 `--exclude-dir=archive`。

知识与阅读条件见 [知识入口](docs/INDEX.md)。详细开发规范见 [开发规范](docs/standards/development.md)。接续已有任务才需要读 [开发入口](dev/INDEX.md)。
