# 开发入口

- 方向与先后：[路线图](roadmap.md)。
- 【待填：有实际工作时，链接活跃计划或任务，并说明接手时先读哪一份。】

状态与执行记录由对应任务维护。没有活跃工作时直接说明，不预填已通过或已集成结论。已结束记录可归档到根 `archive/dev/` 下的原相对路径。

本入口不预建状态页。有独立协调用途时，按 `scripts/wiki/workflow.md` 的“任务记录与状态页”判断是否需要，避免重复任务记录。已接入执行套件时，按其实际读取契约保留必要记录和固定入口，调整前同步核对读取方。

## 执行套件的项目绑定（采用时填写）

按 `scripts/wiki/workflow.md` 的“与执行套件共用开发入口”填写；未采用套件时删去本节。复用实际来源，不创建空文件；没有的角色写“无”或“未采用”。

| 角色 | 实际来源与维护职责 |
|---|---|
| 任务来源 | 【待填：计划、需求、问题或提交任务的入口与识别方式】 |
| 执行与协调记录 | 【待填：套件规则入口，以及派工、状态、冲突范围、槽位和恢复记录的来源与维护者】 |
| 待处理项来源 | 【待填：已有收件箱或问题系统，或无】 |
| 验证入口 | `python3 scripts/wiki/wiki.py verify --root .`；【待填：结果保存到原任务的位置】 |
| 归档约定 | 【待填：结束条件、归档位置及读取方不再依赖原位置的确认方式】 |
