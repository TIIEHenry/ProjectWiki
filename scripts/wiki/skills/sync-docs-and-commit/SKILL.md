# 同步文档与提交

本技能由 ProjectWiki 提供，随 `scripts/wiki/` 分发，供接入项目同步自己的文档、验证本次改动并完成提交收尾。

读取或自动选中本技能不产生提交、推送或修改外部系统的授权；沿用本次任务的授权范围，已经明确授权的操作不重复询问。

## 确认范围与项目入口

先确定本次任务所在的项目根目录，读取该项目的 `AGENTS.md` 和相关入口；后续路径、配置、工作区、暂存区及 Git 提交均以这个项目为准。识别本次实现、测试、必要文档和无关改动，连同原有暂存内容一起核对，不能把文件在同一路径当作属于同一任务的依据。

文档流程遵循[共享流程与项目适配](../../workflow.md#共享流程与项目适配)。遇到旧规则仍强制逐提交更新状态、分离方案与实施提交等冲突时，按该节处理接入缺口，再继续受影响的收尾操作。

从项目入口找到本次改动对应的需求、现行文档、已有计划和验证入口。只读取与本次工作相关的内容，不按默认文件名另造记录。

只纳入本次授权范围内的改动。同一文件混有其他工作时，按差异选取属于本次任务的部分，并检查最终暂存内容；无法可靠分离时保留现场，说明具体冲突并请求必要的范围澄清。不擅自提交、取消暂存、覆盖或清理其他人的改动。已有无关暂存内容时，先确定能够保留它且只提交本次内容的方法；做不到就停止提交，文档核对仍可完成。

## 按影响同步

- 行为、接口或规则变化使现行正文失实时，在本次改动里更新对应正文和必要引用。内部重构、测试或修复使实现重新符合既有文档时，核对后可以不改文档。具体边界见[同步文档](../../workflow.md#决定或设计变化时同步文档)。
- 更新本次受影响的需求条目、实际使用的计划和审查记录，使用项目登记的状态与写法；不把 ADR 当作进度计划。普通修复不补造计划、ADR 或设计页，也不因文件存在就更新所有状态页和路线图。依据可以写在提交信息中，详见[任务记录与状态页](../../workflow.md#任务记录与状态页)。
- 本次确需结束或归档计划、待处理项或审查记录时，按[生命周期与归档](../../workflow.md#生命周期与归档)核对结束条件和引用，再使用 Wiki 工具处理。

实现、测试和本次必须同步的文档一起形成完整改动；不强制方案先单独提交，也不把无关工作并入本次提交。

## 验证并处理提醒

从当前项目的验证入口选择与影响范围一致的检查，在该项目根目录使用其配置中实际登记的 `verify` 检查名，命令见[工具入口](../../README.md#常用命令)。需要保存验证记录时使用 `verify` 的实际输出，说明输入、范围、失败和未检查项；工作区检查通过不能代替暂存内容的检查。

提交提醒按[配置与规则](../../reference.md#提交时的文档提醒)处理，不额外要求每次改文档或写复核 trailer。已知正文失实仍当次更新；仅有单次 `[info]` 不需补记录。累计复核的 `[agent]` 提醒须实际核对后处理。遇到 `[user]` 先核对既有用户授权，未涵盖才确认。

## 按授权提交并报告

只有提交已获授权时，才暂存本次改动；核对最终差异并通过项目适用的提交检查后创建提交。用户只要求核对文档时，完成核对即可，不因技能名称含 `commit` 而提交。

按项目约定写明修改原因及必要验证依据。提交钩子失败时检查输出和仓库状态，修复本次范围内的问题后重试，不跳过钩子；不要假定失败前已经或尚未产生提交。未获授权不推送、不改写已有提交。

结束时检查提交实际包含的内容与剩余工作区状态，简要报告必要的文档同步、实际验证范围和结果、提交结果或未提交原因。保留其他工作；不用另建一份收尾报告或逐项列出未采用的文档类型。
