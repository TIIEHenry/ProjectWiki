# 给项目接入 ProjectWiki

本技能由 ProjectWiki 提供，操作对象是用户指定的业务项目。目标是让现有文档支持真实开发任务，并使必要检查生效；按项目需要采用功能，不把模板中的每种文档都建一份。

## 确定目标与来源

先定位目标项目根目录，读取它的 `AGENTS.md`、相关入口、Git 工作区和暂存区状态。所有接入修改、项目配置和验证均以目标项目为准，保留已有未提交和未跟踪内容。

首次接入需要可读的 ProjectWiki 来源，其中包含 `docs/guides/adoption.md`、`templates/` 和 `scripts/wiki/`。从用户提供的路径或已知工作区定位并核实这些文件，把来源和目标分清；从源仓打开本技能不表示目标就是源仓，从项目内打开也不表示项目包含完整模板。来源只读，不用本机绝对路径在目标文档中建立依赖。

按来源中的 `docs/guides/adoption.md` 读取本次需要的接入步骤；规则、模板和工具取自同一来源。来源不明或材料缺失时先完成目标调查，说明缺少什么；不要猜测仓库地址、伪造模板或把未完成的接入报告为完成。仅补齐现有工具配置时，可用目标中已有的完整工具包和[配置说明](../../reference.md)，不强制重新获取来源。

## 判断需要补什么

选一项项目真实的功能修改和一项维护任务，沿入口找到需求、约束、代码和验证方式。针对找不到、重复或失实的部分补足导航和正文，不先搭空目录。

分别核对内容和流程：有效正文、编号、目录及状态写法优先保留并登记；文档开发流程按[共享流程与项目适配](../../workflow.md#共享流程与项目适配)迁移。逐条清理与共享流程重复或冲突的旧要求，同步原入口、检查器及其他读取方；必要例外按该节说明依据，不因旧规则更严格就保留。暂存检查与工作区检查输入不同，不能只因名字相近就删掉其中一个。处理后的规则写回现有入口，不新增长期维护的流程清单。

不要把源仓的产品需求、开发约定或 demo 业务内容当作目标项目事实。必要的记录与状态边界见[开发流程规则](../../workflow.md)，已有历史的登记方法在[配置说明](../../reference.md)中按 `adopted_at`、`status_frontmatter` 或 `baseline` 定向查找。

## 合并最小接入内容

- 对照来源模板，补缺失入口并合并现有文件；保留业务、接口、安全约束和有效内容，旧文档流程要求按上节处理。路径移动前核对引用，确需迁移时使用[工具命令](../../README.md#常用命令)，不顺手整理整个仓库。
- 首次接入复制完整 `scripts/wiki/` 工具包，包括说明、技能和钩子。目标已有同名文件时先比较，缺失文件按需补齐；已有工具的版本差异或本地修改单独说明，不以补齐接入为由覆盖升级。
- 在目标 `docs/wiki.json` 中登记实际文档范围、入口、模块和已有编号，合并已有配置、阈值与测试命令。已有历史问题按来源指南处理，不用整目录排除、扩大基线或放宽门禁掩盖本次新问题。`adopted_at` 只能指向实际存在的接入提交；尚未提交就说明待完成项，不为填它擅自提交。
- 合并目标的 `AGENTS.md` 和搜索忽略规则。详细流程链接复制后的工具说明，技能只提供按任务读取的入口；不宣称宿主原生技能发现已经安装。
- 将项目已有的测试、构建和文档检查登记到 `verify`；对照真实代码与文档建立 `remind` 对应关系。旧提交导致累计欠账时实际复核相关正文，不通过随意提高阈值或虚写复核说明清零。核对不完的范围明确留待处理。

## 接入钩子并验证

先核对现有 Git 钩子和当前生效的配置，再按[安装 Git 钩子](../../README.md#安装-git-钩子)接入。已有钩子管理器或脚本时合并 Wiki 检查，保留仍适用且有独立用途的原检查；等效检查只执行一次，旧文档流程检查随规则一起迁移，不覆盖无关配置。只在目标项目本地配置，遵守用户给定的操作范围；不修改全局 Git 或宿主设置。没有 Git 仓库时不为通过门禁自行初始化，只报告能够完成的检查。

运行目标登记的 `verify`，保留其真实输出；用 `doctor` 核对已启用的检查和工具无法判断的范围，用 `remind` 核对实际提醒。命令和退出码见[工具入口](../../README.md)，配置按[规则说明](../../reference.md)读取。

按来源指南的接入验收，核对真实阅读路径、需求与测试追踪、必要模块和实际暂存快照。需要暂存验证但未获准改变目标暂存区时，在隔离副本或临时索引验证候选内容，说明它不是原暂存区；不要纳入或取消暂存其他任务。钩子行为在临时 Git 仓库验证：普通代码与测试修复在未达复核阈值时能提交，暂存区仍有断链时不能被工作区修复掩盖。临时试验不改变目标项目的提交历史。

配置未进入被检查的索引、钩子未启用或检查只覆盖部分范围时，如实列出，不能用退出码为零代替完整接入验收。

## 交付接入结果

简要说明目标项目、采用的来源、实际修改、验证输入与范围、仍未完成的接入项。不为汇报新建计划、状态页或审计报告；确需后续处理的事项放进项目现有待办。接入完成后的日常文档同步使用[同步文档与提交](../sync-docs-and-commit/SKILL.md)。

接入请求本身不等于提交或推送授权。用户已经授权的范围继续完成；未授权的提交、推送和其他项目修改不执行。
