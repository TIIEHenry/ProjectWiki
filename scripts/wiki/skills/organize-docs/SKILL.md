# 整理存量 Wiki 文档

在当前业务项目中整理用户指定的主题、目录或批次，保留有效知识、历史来源和未完成工作。本技能只处理 Wiki 文档及其引用。

文档流程遵循[共享流程与项目适配](../../workflow.md#共享流程与项目适配)，按该节区分实际路径、必要例外与尚未迁移的冲突。

## 确定本批范围

- 读取项目 `AGENTS.md`、已有文档入口和实际 Wiki 配置，确认业务项目根、知识与过程文档、历史根及本批边界。信息已明确时直接使用；项目或整理范围有实质歧义时再询问。
- 查看相关未提交改动，只处理获准整理的内容。源、目标或需改写的引用有并行修改且无法安全分离时，暂停受影响部分，继续独立可处理的部分，不覆盖他人工作。
- 按需阅读[生命周期与归档](../../workflow.md#生命周期与归档)、[任务记录与状态页](../../workflow.md#任务记录与状态页)。命令查[工具入口](../../README.md)，配置和规则按名称查[配置与规则](../../reference.md)，固定写法查[格式说明](../../formats.md)。

## 判断去向

先通读候选正文及相关入口，核对当前职责、适用范围、引用、历史来源和剩余事项。优先原位修订或补导航，其次合并；只有位置不合适或生命周期已结束时才迁移或归档。

- **保留与修订：** 现行需求、接口、设计和仍约束当前行为的决策记录（ADR）留在所属知识范围原位维护。时间久、篇幅长或没有入链都不能单独作为归档理由；无入链但仍有效的知识应补入口。
- **合并：** 先确定权威正文，区分真正重复和适用对象不同的内容，逐项保留独有约束、例外、来源与证据。无法确定哪份结论有效时，保留差异并提出待核对项，不把冲突写成统一结论。
- **迁移：** 仅在现有位置不符合实际职责时搬迁；保持知识页路径稳定有利于引用。不要为了目录整齐重分全仓，也不默认给每个模块拆状态页。
- **归档：** 按生命周期规则判断，先将可复用结论写回当前知识。标为已完成的计划仍有未勾选步骤时，依据已有决定核对去向与状态；没有去向的保持原处并说明问题，不能因整理请求就取消工作或勾选完成。等待、阻塞和未完成工作不能靠归档消失。
- 审查目录只有全部方案实施或转出后才整体归档；被替代的决定或废弃方案保留当时理由，并写明原因、适用范围和替代目标。

合并或停用旧正文时，保留需求、问题等已有编号及其可追溯关系，更新当前入口到权威正文；历史证据仍指向当时记录，不能一律改成最新结论。需要保留旧来源时按归档规则处理，不把独有内容直接删掉。

## 执行正文与路径调整

先完成必要的正文修订和未完成事项转出，再对实际路径操作预览；正文合并本身不是工具自动完成的工作。

1. 按[归档规则](../../reference.md#归档先预览再执行)或[搬迁规则](../../reference.md#搬迁文档)使用 `archive` 或 `move` 的只读预览，不手工移动。
2. 核对预览中的实际来源、目的地、移动文件（包括非 Markdown 文件）和入链、出链改写清单，确认都属于本批授权范围。目录移动也要检查随行资产与未跟踪内容。
3. 预览不包含所有引用。按实际读取方检查代码注释、脚本、配置、排除目录和已知外部消费者；固定入口、恢复或验收依据仍被读取时，先解决依赖再迁移。带锚点的引用和外部书签按需保留跳转并单独核对，不能假定跳转页会传递锚点。
4. 无冲突且范围已获授权时，使用该次预览返回的 `plan_sha256`，通过 `--apply --expect` 执行，无需额外请求一次确认。输入变化导致计划失效时重新预览；不要手写或复用旧哈希。
5. 来源或目的身份冲突、目标已存在、需手工改写或无法安全处理的修改，仅停止相关操作并说明障碍，不覆盖、不自动改名绕过冲突。执行失败时按工具实际报告检查工作区与回滚结果，不假定完全恢复。

新建正文或跳转页前按工具入口使用 `check-new` 核对完整路径与历史。若合并后更改标题或章节，核对旧锚点；当前入口指向当前正文，历史入口保留历史含义。只有项目已配置的生成目录受影响时才更新生成目录，不手改生成结果。

## 核对与交付

- 检查差异，核对本批有效知识、独有内容、编号、历史来源和未完成事项均有明确去向，引用没有因合并或迁移改变含义。
- 查看路径操作返回的 `after_check`；有后续正文修改时，再按需运行 `check`。需要验证记录或其他登记检查时，先核对配置中的命令，再按实际范围运行 `verify`，记录使用其真实输出，细则见[验证记录](../../reference.md#验证记录)。
- 简要说明本批实际输入与范围、处理结果、未完成或受阻部分、运行的检查及限制。只通过部分检查时不能报告全部通过，文档检查也不能证明业务结论或实现正确。
- 不为每篇文档新建报告或计划；剩余工作写入项目已有的待处理位置并保留来源。默认不暂存、提交或推送。
