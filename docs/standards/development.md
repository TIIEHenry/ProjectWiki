# ProjectWiki 开发规范

## 修改前

阅读受影响的需求与设计，确认修改属于规则调整、工具行为变化、模板变更还是示例变更。接续已有工作时，核对任务状态、代码差异和验证对象。

改动应保持三个使用场景一致：ProjectWiki 自身使用、模板复制接入、参考项目运行。新增强制字段或门禁时，用一个小项目验证其必要性。

## 实现要求

- 本地工具以 Python 3.10 及更新版本运行，第一版仅使用标准库。
- 检查保持只读。预览、生成和写入接口清楚区分，不自动暂存或提交。
- 配置完整解析，字段错误明确报告。不能在解析失败时静默采用另一套默认值。
- 路径按目标仓库与引用所在文件解析，检查大小写，不使用仓库根回退来掩盖错误相对链接。
- 暂存检查的配置、正文和链接目标来自同一 Git 索引快照；缺失时不能读取工作区内容补齐。
- 归档预览保留原路径和文件名，展示冲突与引用影响。第一版不提供自动归档写入。
- 不清理其他协作者的文件。共享工作区按文件范围分工。

## 验证与文档更新

```bash
python3 -m unittest discover -s tests -v
python3 scripts/wiki/wiki.py check --root .
python3 scripts/wiki/wiki.py check --root demo
python3 -m unittest discover -s demo/notes/tests -v
```

工具行为变更需要运行相关反例测试；配置或目录变更需要检查实际接入范围；模板变化需要在临时目录复制验证。仅修改文字时，检查引用与表达即可，不重复运行无关代码测试。

行为、接口或目录职责变化时，原位更新对应知识。知识没有变化时，不为形式完整而新增设计文档。当前目标或集成状态改变时更新工作记录，不把每次小修复追加成全局状态流水。

## 验证记录

记录命令、输入范围、实际结果和已知限制。代码快照与之后写入的验证记录分开说明；当前仓库没有 Git 提交时，使用文件内容哈希标识被测代码。

检查通过只能说明实际覆盖的规则成立。未运行的检查、无法访问的范围和不支持的语法应明确列出。

## 文档表达

新建与修改稳定知识时遵守[中文技术文档规范](writing.md)。模板中的提示语也需要明确、简短，避免诱导 Agent 生成空泛的背景、重复总结或无实际内容的章节。
