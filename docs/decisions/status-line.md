# 决策：计划和决策记录用正文首行写状态，由工具读取

状态：当前有效。范围：ProjectWiki 工具与接入项目的计划、决策记录。

## 问题与约束

首版工具不读取正文里的状态。因此有两类问题机器发现不了：

- 入口页仍链接到已经被替代或废止的文档，读者按旧结论工作。
- 计划已经完成或取消，却一直留在 `dev/` 并标着"执行中"，进行中的工作列表因此失真。

约束：正文不强制 YAML frontmatter（[文档模型](../design/document-model.md)）；状态要让人直接读懂；工具只用 Python 标准库。

## 决定与理由

计划和决策记录在一级标题下第一行写状态，格式是 `状态：<值>。`，也可以写 `Status: <value>.`。后面可以接范围等说明。例如：

```markdown
# 决策：标题按 Unicode 码点计数

状态：当前有效。范围：标题校验。
```

工具把状态值归入固定的几类：draft、active、blocked、current、finished、superseded、retired、open。每类的默认值见[工具读取的写法](../../scripts/wiki/formats.md#计划决策记录和待处理项的状态行)。

每个类别默认只保留一个中文值和一个英文值。审查判定、需求状态和行首关键词也按这条处理。项目可以在 `docs/wiki.json` 的 `status_values` 里补充自己的值，例如 `{"采用": "current", "进行中": "active", "评审中": "draft"}`。工具不把项目同义词永久写进默认值表。

工具据此做三件事：

1. 入口页链接到 superseded 或 retired 的文档时报错；其他现行页面这样链接时给警告。决策记录之间互相引用不算，因为新决定需要指向它替代的旧决定。
2. `remind` 提醒长期没有更新的 active 计划、已经 finished 却仍在 `dev/` 的计划，以及缺少状态行的计划。
3. 计划和决策记录的状态值无法识别时给警告。

选择首行文字而不是 frontmatter：人在渲染后的页面上能直接看到状态，三个参考项目的 frontmatter 都出现过合并损坏和字段取值膨胀。

## 替代方案

- **YAML frontmatter。** 机器读取方便，但渲染后不一定可见，长期运行的项目也容易让类型和状态值膨胀。没有采用。
- **在 `wiki.json` 里登记每篇文档的状态。** 状态和正文分开存放，改了一处容易忘改另一处。没有采用。
- **继续不读状态。** 上面两类问题只能靠人工复核，实践中长期没有被发现。没有采用。

## 影响与退出条件

- 计划和决策记录多了一条格式要求。缺状态行只给警告，不拦截提交，旧仓库可以逐步补齐。
- 工具能识别的只是状态值，不能判断状态写得对不对。一份实际已经完成、却仍写着"执行中"的计划，只能靠 `plan-stale` 的时间提醒发现。
- 如果以后大多数接入项目改用 frontmatter，可以让工具同时读取 frontmatter 的 `status` 字段，再评估是否替代本决定。
