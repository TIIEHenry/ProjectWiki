# ProjectWiki 规范

这里是文档系统本身的规范：接入项目怎样组织文档、怎样维护和检查。参考项目的业务文档位于 [`demo/docs/`](../demo/docs/INDEX.md)。

| 什么时候读 | 文档 |
|---|---|
| 确认系统要满足的要求和验收条件 | [需求](requirements/projectwiki.md) |
| 决定文档如何分类、引用和展开 | [设计原则](principles/document-system.md) |
| 查本仓库各目录的职责 | [目录与模块结构](design/module-structure.md) |
| 判断当前知识、过程记录与历史的效力 | [文档模型](design/document-model.md) |
| 新建、移动或归档文档 | [生命周期与归档](design/lifecycle.md) |
| 运行、接入或扩展检查工具 | [自动化设计](design/automation.md) |
| 安排需求、计划、ADR 和审查 | [开发流程](guides/workflow.md) |
| 了解计划和决策为什么用正文首行写状态 | [状态行决策](decisions/status-line.md) |
| 了解需求编号怎样贯穿设计、计划和测试 | [需求追踪决策](decisions/requirement-traceability.md) |
| 了解核对记录、复核期限和 OKF 导出的取舍 | [核对记录与 OKF 决策](decisions/verification-line-and-okf.md) |
| 了解哪些步骤交给工具执行、哪些仍由人或 Agent 判断 | [机械步骤自动化决策](decisions/automation-writes.md) |
| 创建或审查中文技术文档 | [写作规范](standards/writing.md) |
| 修改 ProjectWiki 的代码、模板或示例 | [开发规范](standards/development.md) |
| 给现有项目接入这套系统 | [接入指南](guides/adoption.md) |
| 按模板建立新内容 | [模板说明](../templates/README.md) |
| 查状态行、核对行、需求条目、审查问题的写法和编号分配 | [工具读取的写法](../scripts/wiki/formats.md) |

规范原位修订，旧版本由 Git 保存。还没做的事见[待办](../TODO.md)，版本变化见[变更记录](../CHANGELOG.md)。
