# ProjectWiki 需求

## 使用者与场景

ProjectWiki 面向需要维护项目知识的开发团队，以及在同一仓库中工作的编码 Agent。接入项目可以是单模块工具，也可以由多种构建系统组成。

主要场景包括：新成员理解项目、Agent 定位修改范围、开发者维护接口与设计、协作者接续任务，以及维护者追溯历史决定。

## 功能要求

| 编号 | 要求 | 验收方式 |
|---|---|---|
| PW-01 | 稳定知识、开发过程、历史分开组织 | 根目录存在职责清楚的 `docs/`、`dev/`、`archive/` |
| PW-02 | 稳定知识至少包括需求、原则、设计和开发规范 | 读者能找到范围、约束、当前设计及实施规则 |
| PW-03 | 内容适合人阅读，也便于 Agent 按任务展开 | 入口说明阅读条件，正文解释必要术语，关键规则可直接读取 |
| PW-04 | 模块内部知识靠近源码，全局入口能够定位模块 | 示例包含模块 README、模块 docs 和全局导航 |
| PW-05 | 当前知识保持稳定路径 | 修改示例中的业务规则时可以原位修订相关知识页 |
| PW-06 | 归档保存原路径，避免覆盖与无意义改名 | 预览显示 `archive/<原相对路径>`，同名目标被明确报告 |
| PW-07 | 新建文档前检查对应历史 | 新建检查提示同源历史，不把所有同 basename 文件视为冲突 |
| PW-08 | 默认搜索降低历史噪声，历史仍可按需查阅 | 普通 `rg` 与显式历史检索分别验证 |
| PW-09 | 文档检查与实际接入可验证 | 检查报告说明范围和失败项，反例测试能发现错误 |
| PW-10 | 其他项目可通过阅读本仓库自行接入 | 接入指南、模板与 demo 能组成完整操作路径 |

## 质量要求

文档使用具体、清楚的技术语言。编写者需要删除无信息量的铺垫、翻译腔和未定义的内部行话。机械检查只辅助发现问题，文风结论仍需阅读全文。

工具保持本地可运行，检测默认只读。迁移操作不得静默覆盖内容，也不得把不完整检查报告为通过。

## 第一版边界

第一版交付仓库结构、介绍与设计文档、接入模板、参考项目和本地检查工具。自动归档写入、任意 Markdown 方言、任意开发工具的配置推断以及完整依赖图不属于第一版承诺。

本文件持续维护需求。具体实施状态见[开发入口](../../dev/INDEX.md)，任务完成后仍然有效的要求继续保留。
