# 目录与模块结构

本文件持续描述 ProjectWiki 当前结构。目录变化时原位更新本页。

| 路径 | 职责 |
|---|---|
| `README.md` | 项目介绍与接入入口 |
| `AGENTS.md` | 可直接执行的全局规则与阅读路由 |
| `docs/` | ProjectWiki 自身的需求、设计、原则和规范 |
| `dev/` | 开发流程、路线图、计划、待决事项与执行记录 |
| `archive/` | 已结束工作与整体失效内容 |
| [`scripts/wiki/`](../../scripts/wiki/README.md) | 可复制的本地文档工具 |
| `tests/` | 文档工具的反例与行为测试 |
| `templates/` | 接入时使用的最小模板 |
| `demo/` | 独立配置、可运行的 NoteBox 参考项目 |
| `tmp/` | 讨论过程中其他窗口保存的草案，不属于当前知识 |

## 文档层

`docs/requirements/` 说明系统要解决的问题与验收要求。`docs/principles/` 说明组织知识时必须保持的约束。`docs/design/` 解释当前结构与工具行为。`docs/standards/` 规定开发和写作要求。`docs/guides/` 提供具体操作步骤。

开发流程的执行入口在 `dev/workflow.md`。路线图、计划和决策通过链接关联，当前工作从 `dev/INDEX.md` 进入对应计划。需要跨计划汇总时再建立状态页。

## 参考项目边界

`demo/` 是独立项目样本，使用自己的 `docs/wiki.json`。根检查配置排除 demo 的内部文档，再单独以 `--root demo` 验证，避免把两个项目的角色与预算混为一体。

参考项目中的模块布局不限制接入项目。已有仓库可以继续使用 `core/`、`packages/` 或其他源码布局，只需登记模块入口与文档根。

## 工具与模板

检查器读取目标项目的配置，所有配置路径相对目标项目根目录。模板提供结构和写法，复制后必须替换示例目标、模块和验证命令。

其他项目的 Agent 应通过[接入指南](../guides/adoption.md)选择最小内容集合。已有有效文档可以直接登记，不需要先移动全部文件。
