# 文档自动化

## 当前实现

入口是 [`scripts/wiki/wiki.py`](../../scripts/wiki/wiki.py)，需要 Python 3.10 或更新版本，使用标准库。默认配置为目标项目的 `docs/wiki.json`。

| 命令 | 当前作用 | 是否修改文件 |
|---|---|---|
| `check` | 检查登记范围、入口、路径、支持的链接与预算 | 否 |
| `check --staged` | 从捕获的 Git 索引检查规则，并提示新增文档对应的历史 | 否 |
| `check-new <路径>` | 查当前位置及对应归档位置 | 否 |
| `archive <路径>` | 预览整页目的地、冲突与受影响引用 | 否 |
| `index` | 向标准输出生成确定性的 JSON 目录 | 否；重定向输出由操作者决定 |
| `index --check` | 比较登记的 JSON 目录与当前输入 | 否 |
| `doctor` | 报告配置、精确忽略规则、ProjectWiki Git 钩子是否安装，以及接入能力边界 | 否 |
| `remind` | 汇总各组代码自上次文档更新或复核以来的累计改动 | 否 |
| `remind --staged` | 提交时提醒同步文档、确认需求变更；累计量超过 `block_at` 时拦截 | 否 |

所有子命令接受 `--root` 和 `--config`。检查类命令接受 `--json`；`index` 始终输出 JSON。工具没有自动归档写入接口。

## 配置

配置路径均相对 `--root` 指定的项目根目录，不相对配置文件所在目录。实际例子见[本项目配置](../wiki.json)和[参考项目配置](../../demo/docs/wiki.json)。

| 字段 | 含义 |
|---|---|
| `version` | 配置版本，当前为 `1` |
| `project_name` | 项目显示名称 |
| `roots` | 文档根与角色：knowledge、process、archive |
| `archive_root` | 可选的主归档目标，必须是已登记的 archive 角色目录 |
| `modules` | 模块名称、源码根和入口；模块 docs 路径可省略 |
| `entrypoints` | 必须存在的入口文件 |
| `pages` | 按需登记页面角色、字符预算、ID 或作用域 |
| `exclude` | 明确不由当前项目检查的目录或文件模式 |
| `generated_index` | 可选的 JSON 生成目录路径 |

当前正文不强制提供 YAML frontmatter。配置使用完整 JSON 解析和字段校验；文档需要结构化流程状态时，先明确用途再增加专门规则。

## 检查范围

检查器扫描登记根、模块文档和入口，另行发现未登记且未明确排除的 `docs/` 目录。扫描独立于 `.ignore`，历史文档仍进入检查。

当前入口缺失、重复的当前 ID、错误本地链接、缺失锚点与入口超预算会产生错误。归档正文的链接问题降为警告，避免要求历史始终指向现行文件。普通外部链接不联网验证。

历史身份依据登记的归档根判定，现行页不能通过单页配置声明 `archive` 来降低检查级别。当前文档中的相对本地链接越出项目根时失败；本机绝对路径等不支持的普通链接给出可移植性警告，必需导入无法验证时失败。

第一版支持常规行内链接、引用式链接、图片、ATX 标题、显式 HTML 锚点，以及 `AGENTS.md`、`CLAUDE.md` 中独立一行的本地 `@路径` 导入。路径按引用所在文件解析，检查精确大小写，不提供仓库根容错回退。

锚点使用固定的标题规范化实现及反例测试。工具不是 Markdown 渲染器，不承诺覆盖所有方言、宿主导入语法、正文语义或运行时契约。

## 工作区与暂存快照

普通 `check` 读取工作区。`--staged` 捕获 Git 索引中的文件模式与 blob ID，随后通过 blob 读取配置、正文和目标。工作区修复不能掩盖暂存区错误。

暂存检查同时捕获 HEAD 作为路径新增的比较基线；尚无首个提交时使用空基线。新增文档对应的历史也从已捕获的索引读取，存在时给出警告。报告标明基线与索引标识，不推断新旧正文是否属于同一主题。

没有 Git 仓库、索引存在冲突、必需配置未暂存或输入不可读时，报告为 `incomplete` 并返回非零退出码，不退回工作区继续检查。

首版仅 `check` 支持 `--staged`。`check-new`、归档预览、`index` 和 `doctor` 读取工作区，输出明确标识 `working-tree`；它们的结果不能作为即将提交内容的快照验证。

JSON 报告包含工具版本、输入标识、配置哈希、覆盖根、排除项、错误和警告。当前退出码为：`0` 表示没有错误，可能仍有警告；`1` 表示检查失败；`2` 表示输入或执行条件不完整。

## 索引与人工导航

`index` 生成供机器消费的全量页面目录，包含路径、标题、角色和作用域，也收录归档页。需要当前知识集合的消费者必须排除 `role: archive`，并按用途筛选其他角色。相同输入产生相同输出，不把运行时钟写进结果。它不覆盖人工维护的 `INDEX.md` 阅读路径。

有生成目录的项目可以先输出到临时文件，审查差异后替换，再运行 `index --check`。参考项目已登记生成目录；本项目主导航使用人工表格。

## 新建与归档预览

`check-new` 检查完整原相对路径。当前目标存在时报告错误；对应归档存在时给出历史提示，标准文件名不会永久锁定。

归档目标默认是已登记的根 `archive/`，也可用 `archive_root` 明确指定。旧布局的其他历史根仍参与分类和检查；新建检查不自动推断其目录对应关系，报告会提示这些历史尚需另行查阅。

`archive` 只处理一份完整 Markdown 文件，输出目的地、源内容哈希、同名冲突及入链和出链的机械候选修改。操作者仍需区分当前导航与历史证据。预览不判断主题是否已经退役，也不创建跳转页或修改锚点。

出链目标不存在时，预览报告未解决的引用，不给出看似有效的新路径。目标可定位也只证明路径存在，不能证明所指内容仍是当时的历史依据。

片段归档、批量迁移、自动恢复关系和可靠写入属于后续工作，不能把当前预览命令视为已实现这些能力。

## 提交时的文档提醒

文档漏改通常不是因为规则没写，而是改代码的人或 Agent 没有在合适的时候想起来。提醒挂在提交上：Agent 开发时会频繁提交，所有 Agent 宿主和 Git 客户端都会运行 Git 钩子，这样提醒不依赖某一个宿主的插件机制。

| 触发 | 机制 | 结果 |
|---|---|---|
| 每次提交 | `commit-msg` 钩子运行 `remind --staged --message-file` | 打印提醒，默认不拦截 |
| 累计量 | 同一命令按 `watch` 统计自上次文档更新或复核以来的提交次数与改动行数 | 达到 `threshold` 时提醒；达到 `block_at` 后继续改代码且未复核，则拦截 |
| 会话开始 | `AGENTS.md` 规则要求开始任务时运行 `remind`；宿主支持会话钩子时也可以自动运行 | 汇总待复核的区域 |

计数全部从 Git 历史、暂存区和提交信息计算，不另存状态文件，因此分支、工作区副本和不同机器看到的结果相同。复核过但不需要改文档时，在提交信息最后一段写 `Docs-Reviewed: <名称> <理由>`，计数从这次提交重新开始。

提醒分两类。`[agent]` 由 Agent 自己处理：同步文档，或写明复核理由。`[user]` 表示需求、原则或决策发生变化，Agent 应先向用户确认。决策记录改变时，工具列出链接到它但本次没有改动的现行文档；直接复述结论却没有链接的地方需要另行按关键词搜索。

确定的结构错误由 `pre-commit` 的 `check --staged` 拦截。提醒类问题默认不拦截，避免每次提交都被打断后 Agent 养成随手写复核理由的习惯。`block_at` 是累计欠账的上限，不配置时只提醒。工具不判断文档内容与代码是否一致，也无法阻止 `--no-verify`。

## 实际门禁与后续范围

`doctor` 核对配置、精确的归档忽略条目，以及当前生效 Git 钩子目录中的 ProjectWiki 钩子是否存在、可执行并调用对应命令。其他钩子管理器与构建任务报告为未知；钩子文件存在也不能证明每次提交都执行了它。

接入项目需要自行把同一检查命令接入现有流程并运行反例。未启用的接入不能在文档中描述为已启用。

第一版尚不提供正文风格判定、需求语义验证、流程状态一致性、配置与实现的领域对账、存量问题基线管理或自动归档写入。写作质量按[写作规范](../standards/writing.md)人工复核。增加存量基线时，应按稳定问题指纹比较新增项，避免只比较总数。
